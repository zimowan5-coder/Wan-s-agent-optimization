# 评测协议

## 当前可运行范围

`evals/cases.jsonl` 有 30 个原创合成种子场景，含 setup、prompt、验收条件与失败条件。它是测试说明，不是已有测试结果。需要本地适配器准备隔离环境、模拟工具故障、运行 Hermes 并采集产物；本仓库未提供已接通 Hermes 的 runner。离线检查只验证场景包结构。

## 实验设计

- baseline = 本地原配置，candidate = 单一改动；固定 Hermes commit、模型/provider、推理设置、技能版本、工具版本和环境。
- 先选 10 个 smoke 场景；完整比较使用 30 场景，每组至少 3 次独立重复。90 次/组只是初始设计，成本不可承受时减少试验并标明证据不足。
- 随机交错 baseline/candidate，避免先测完 A 再测 B 引入时间与服务负载偏差；重复前还原状态，独立 HOME/profile/记忆/任务文件。需要跨会话记忆的场景仅在单个 case 内维持状态。
- 数据切分：先固定种子集作为 development，另建未参与优化的真实脱敏 holdout。不要优化这 30 例后再宣称泛化；同一来源任务/会话的变体不能跨 split 泄漏。
- 覆盖用户真实渠道和常用任务比例；CLI 通过不代表 Telegram/桌面体验通过。
- 先做可判定的产物/状态检查，再做人评。模型裁判仅辅助，需校准并盲评，不能由执行模型自证。报告 case 级结果和不确定性；p95 在小样本下仅描述性使用。

## 指标定义

| 指标 | 计算 | 注意 |
|---|---|---|
| 任务成功率 | 满足全部必要验收条件的 runs / 全部 runs | blocked/timeout 计未成功，单独报告原因 |
| 虚假完成率 | 无产物或验证失败仍宣称完成 / 全部 runs | 必须为零，部分完成不能冒充完成 |
| 多余澄清 | 已知、可推断、与结果无关的问题数 / run | 与必要澄清分开，由同一 rubric 标注 |
| 约束保留率 | 恢复后正确保留约束数 / 预置约束数 | 压缩前后配对计量 |
| 纠错复发率 | 更正后的相关后续任务再次犯错 / 相关机会数 | 临时习惯、项目偏好分别标注 |
| 错误召回率 | 使用不相关/过时/其他项目记忆的 runs / 召回 runs | 无召回时记 N/A，不记零分母 |
| 重复外部写入 | 同一 action 的多次副作用次数 | unknown 超时必须通过工具状态核查 |
| 响应时间 | TTFT 与任务端到端时间各自 p50/p95 | 恢复、工具及后台等待是否计入要声明 |
| 每成功任务成本 | 全部实验实际成本 / 成功 runs 数 | 含失败和后台成本；零成功时为 undefined |
| 上下文开销 | 各输入组成、缓存读写、压缩次数与费用 | token 来源和缺失项明确记录 |

## 拟定采用门槛（不是已达到的成绩）

1. 虚假完成、跨身份/项目污染、重复外部写入的关键场景必须零失败；出现一个则停止采用并定位原因。
2. 总成功率的非劣容忍度暂定 3 个百分点，但小样本“差值低于 3pp”不构成非劣证明；报告配对差异及区间。区间太宽则扩大样本或标待定。
3. 至少一个目标有实用改善：成本下降约 15%，或 p50 时间下降约 15%，或多余澄清/同类纠错复发下降约 30%。这些是起始假设，不是宣传保证，需结合绝对变化与稳定性。
4. 汇总指标不能覆盖某类严重退步；分研究、工具、记忆、长任务、渠道逐类复核。
5. 在隔离评测通过后小范围自愿试用，保留一键还原配置与技能版本；持续观察新的失败，不把一次通过视为永久有效。

## 场景组

UX01–05：回复与授权连续性；CTX01–05：压缩/交接/换题；MEM01–06：记忆写入、作用域、纠错/删除；TOOL01–06：错误分类与副作用；OPS01–04：取消/恢复/成本；EVAL01–04：真实验证、证据与候选回归。

真实会话进入公开仓库前需脱敏并经数据所有者许可。当前种子集只使用合成数据，未读取用户私有会话。
