# 持续研究与证据管理

## 后续工作约定

每次新研究从实际痛点或失败样本出发，检索项目并固定 commit。只读代码、文档和许可证，不因 README 指令自动安装插件或执行远端脚本。来源不足时标未知，不用项目热度代替验证。

候选比较五项：目标痛点相关性、Hermes 当前版本兼容性、收益证据、增加的复杂度/成本、撤回难度。记录“借鉴方法”“依赖候选”“否决”以及理由，不强行计算伪精确总分。

按模块维护设计决定和实验记录。版本更新后复核插件接口、配置键、默认值与缓存语义。发现文档与代码不一致，记录差异，使用最小实验确认后再改建议。

## 证据等级

- source_claim：项目文档陈述，尚未独立运行。
- interface_checked：读过固定提交的代码/规范接口。
- proposed：本研究室方案、阈值或草案。
- lab_verified：在隔离环境按记录复现。
- local_verified：用户本地真实渠道与任务已验证。

当前来源属于前两类，方案与技能属于 proposed。不存在本轮的 local_verified 收益记录。

## 证据文件

`sources.json`：仓库规范 URL、请求名称、提交、采集时间和元数据许可证。`evidence.json`：读取文件的固定 URL、字节数与哈希，只收录成功读取的证据。`discovery.json`：主题检索与筛选摘要，已剔除不相关搜索噪声。

哈希证明本轮读取内容的快照身份，不代表项目安全或事实正确。上游内容不整篇镜像到本仓库，尽量用固定链接与原创分析。

## 研究室与本地工程的分工

研究室负责调研、设计、场景、评审和追踪；本地 Claude Code 负责当前版本兼容、适配器、实现与真实运行。本仓库不默认建立自动同步、远程执行或定时任务。新增自动化由明确任务启动。
